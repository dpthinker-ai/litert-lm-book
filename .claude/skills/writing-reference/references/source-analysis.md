# 两本参照书风格分析 · 工作笔记（汇总用）

## 我的第一手阅读（已完成）

### 《推理工程》pp1-28（前言、ch0、ch1、ch2 开头）
- 前言叙事弧：2022 ChatGPT 当天全球只有几百名推理工程师 → 平行时间线假设 → "三年后，事实证明" → 开放模型寒武纪大爆发。时间线叙事 + 具名公司/数字锚定
- 章首一句话定纲："推理工程通过优化生成式模型的生产服务化，为 AI 产品带来速度与规模。"（p17）
- 单句成段做转折支点："在实践中，优化往往是在寻找恰当的平衡，而不是将某一因素最大化。"（p17）
- 类比具体展开后立即映射回来：NFL 球员（相扑/短跑/举重各有专长）→"同样，你的推理系统必须经过优化，以满足你的模型、你的产品以及你的流量的特定需求"（p17）；教练选材类比（篮球教练找最高的，体操教练从最矮的挑，p18）
- 排序断言重排读者优先级："模型性能优化中最重要的决策，不是运行时引擎，也不是推测算法，而是你一开始选择使用哪个模型。"（p20）
- 定义句干净："模型评估，或称 evals，是系统性衡量模型智能的实践。"（p20）；"蒸馏是使用一个大型'教师'模型训练一个较小的'学生'模型，使其模仿大模型行为的过程"（p22）
- 对比句收拢："微调是教会模型在某个特定领域中表现得更好，而蒸馏则是教会模型如何模仿更大模型的行为，无论这些行为是好是坏。"（p22）
- 现实校准句（blunt reality check）："蒸馏在现实世界中的应用，明显少于微调。"（p22）
- 误解纠正："较小的模型通常并不是从较大的模型蒸馏而来。相反，这些模型通常是独立训练的"（p22）
- 术语精确化：TTFT 明确但 TPS 不精确 → 感知 TPS/总 TPS/ITL 三分（p23）；"10 毫秒的 ITL 等价于每位用户每秒 100 个 token"（单位换算给直觉）
- 命名天真做法再升级："一种天真的做法是只看平均值（mean）TTFT 或 TPS。然而，这并不能说明全部情况。"→ 右偏分布 → 百分位表（p24），表把统计翻译成体验（"每 10 个请求中有 1 个更慢"）
- 节尾落诊断规则："当推理时间很快、但端到端时间很慢时，你应该把注意力转向基础设施，而不是模型性能优化。"（p25）
- ch2 开篇：先讲为什么需要直觉，再 4 段压缩史（感知机→AlexNet→2017 transformer）；"但真正的故事始于 2017 年"
- 面向工程师的解释："节点是一个简短的程序：它接收输入，将其乘以若干权重，加上某个偏置，然后返回结果。"（p26）
- 机制动机化引入：激活函数先讲问题（matmul 可组合→多层塌缩成单层）再给 ReLU（p28）
- 图注写结论不写名词（"蒸馏能够在一个更小、更高效的模型中保留大模型的行为"）
- 优缺点表（共享推理优点/缺点，p18）；类别调查表（AI 原生应用 8 类，p19）
- 翻译腔存在但不重："为消费级应用工作的推理工程师"

### 《推理手册》pp15-27（LLM 是如何工作的、运行在哪里、关键指标开头）
- 节首定位句+路线图："本页将带你走完整条流水线：文本如何变成 token、模型内部的架构是什么样，以及推理如何经过 prefill 和 decode 两个阶段。"（p15）
- 定义句先行："token 是 LLM 用来处理文本的最小语言单位。"（p15）；"sampling（采样）就是从这个分布中选出下一个 token 的过程。"（p22）
- KV cache 量化动机（与我们 CLAUDE.md 校准例高度同构）："如果没有 cache，生成第 1,000 个 token 时，就意味着要重新计算前面 999 个 token 的 key 和 value；生成第 1,001 个 token 时，又要把这项工作再做一遍。"（p22）
- 当面算账→反直觉结论：FP16 Llama 3 8B，8K 序列 ≈1GB KV cache，80GB GPU 剩 64GB → 理论上限约 60 条序列 → "通常限制服务器可服务用户数量的不是模型权重，而是 KV cache。"（p22）
- 误解纠正："严格来说，LLM 并没有真正的'记忆'。"（p20）
- 具体语言实例落地抽象机制：causal mask → "这就是为什么在 river bank 和 bank account 里，bank 会表达不同含义"（p16）
- 问题式标题贴读者真实疑问："为什么 LLM 推理会很慢?"（p23）
- 口径固定声明（一次性）："除非另有说明，本手册中的 'LLM' 都指 decoder-only Transformer 模型。"（p21 提示框）
- prefill=compute-bound、decode=memory-bound 的交代都带"实际受…影响"的 caveat
- bullet 密度高（成书嫌碎）；CPU/GPU/TPU 12 维大表偏机械；交互组件 PDF 中退化为截图
- 中英夹杂严重处："On-premises deployments mean 在你自己的基础设施上运行"（p26）

- 表格纪律：只用于 X vs Y 对照与多维速查，行是可比维度，不叙事
- 图纪律：49 页仅 3 幅静态图，只给多方交互拓扑配图

### 报告 C（推理工程 p65-118：技术章+模态+生产环境前半）✅
- 技术节共用骨架：瓶颈 motivation→一句定义+作用边界→各变体共享机制→打折扣的收益数字→代价与失效条件→变体逐个（前者的问题→本方案解法→适用推荐）→收尾落选型。且 p71 开篇就把契约告诉读者（"请特别关注每种技术推荐使用的场景，以及它引入的潜在瓶颈或权衡"）

- 段落 2-4 句、一段只说一件事（可学）；列表当叙事（不可学）
- 拆类比比用类比讲得更透：p20"严格来说，LLM 并没有真正的'记忆'"——先立直觉词再当场拆掉，机制随拆随出
