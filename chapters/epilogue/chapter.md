# 尾声 · 出发

> 分析到此完成，接下来是实践。这篇尾声不引新代码，只做三件事：给出几条上手路径，说明如何参与项目，以及展望后续方向。

从第 1 章的三类物理约束（内存容量、内存带宽、功耗与异构），到第二篇完整的推理流水线，再到第三篇针对各项约束的优化，与第四篇的多模态、工具调用、六种语言的绑定，LiteRT-LM 这套端侧推理运行时，我们从里到外分析了一遍。分析的目的是看懂之后能够动手。

## 三条上手的路

你不必从源码编译起步。按你的场景，挑一条最短的：

- **先跑起来、做实验**：用 Python CLI（第 2 章那个 `litert-lm`）。一条命令装好、一条命令跑模型，改参数看变化最快。想把模型接进 Python 程序，用它的 Python SDK。
- **做 Android / JVM**：用 Kotlin SDK（第 11 章）。Gradle 一行依赖，预编译产物，不用碰 Bazel：

  ```kotlin
  dependencies {
      // Android
      implementation("com.google.ai.edge.litertlm:litertlm-android:latest.release")
      // 纯 JVM（Linux / macOS / Windows）
      implementation("com.google.ai.edge.litertlm:litertlm-jvm:latest.release")
  }
  ```

  `Engine`/`Session`/`Conversation` 的用法就是本书前几章那套接口的 Kotlin 镜像；版本号在 maven.google.com 的 `com.google.ai.edge.litertlm` 下查。
- **做 iOS / macOS**：用 Swift package（仓库 README 标注同时支持 iOS 与 macOS；v0.13.1 时为 Early Preview，集成细节以官方 Swift 指南为准）。记得第 11 章那个 `close()` 的教训：会话用完主动释放，别等 ARC。
- **做网页**：用 Web SDK，npm 安装 `@litert-lm/core`，或直接从 CDN 以 `+esm` 导入。核心编成 WASM 在浏览器里跑，推理全程在本地；数 GiB 的模型文件要随应用分发或首次启动时下载，预留好带宽与缓存策略。

三条路的共同点：**都不需要你懂 C++ 核心**。但读完这本书，当某一条路出了问题（某个后端跑不动、某段生成变慢、某个模型加载失败），你会知道该往哪一层去看。这正是深入分析的回报。

## 参与进来

LiteRT-LM 是开源的，它的 issue 列表汇集了大量真实问题。想参与，先学会分辨：

- 有些 issue 是**硬件相关的疑难问题**：某块特定 GPU/NPU 上的崩溃、某个 SoC 上的数值异常。它们需要对应的设备才能复现，门槛高（本书第 8、9 章引的 `#2281`、`#2227` 就是这类）。
- 有些是**小而清晰的改进**——一个缺失的 API、一处误导的提示、一个能补的边界处理。第 11 章那个 Swift `close()`（`#2589`/`#2613`）就是典型：范围小、有清晰的参照（Kotlin 早有 `AutoCloseable`）、纯增量、低风险。这类适合作为第一个贡献的切入点。

分辨这两类的能力，本身就是这本书想给你的：读懂了机制，你才看得出一个 issue 是"需要特定硬件才能复现"还是"读几个文件就能动手"。（贡献前留意项目的协作约定，比如 Google 系项目通常需要签署 CLA。）

## 往前望一眼

端侧推理这条路，还在快速往前。几个方向值得留意：

- **更激进的量化**。第 7 章讲了 int4。内存带宽约束的压力会继续把量化往更低比特推，也会催生更聪明的量化方式，在"更小"和"够准"之间找新的平衡点。
- **NPU 的普及**。第 8 章说 NPU 最省电但最封闭。随着端侧 AI 成为标配，NPU 的接口会更成熟、覆盖的算子会更多——功耗与异构约束中"异构"带来的负担会逐步减轻。
- **从"生成"到"agent"**。第 10 章的工具调用是个起点。当模型能可靠地调函数、看屏幕、连成多步，端侧就不只是"本地的聊天框"，而是一个装在口袋里、离线可用的智能助手。

这些方向都还没有定论，也正因如此，现在开始参与并不晚。

## 最后

这本书以 LiteRT-LM 为分析对象，讲的其实是一类更普遍的工程问题：在严格的物理约束下，让大模型推理做得成、做得稳、做得快。这些约束不会消失，但边界在移动：第 7 章的量化、第 8 章的 NPU，都在放宽其中某一项。你手里现在有第 1 章的估算方法（decode 吞吐上限公式），和一整套被真实代码验证过的做法。

挑一条最短的路，今天就把第一个模型跑起来。
