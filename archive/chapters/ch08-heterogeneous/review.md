## 本轮已纠正的关键事实

- Pixel CPU 亲和性只覆盖硬编码的 Tensor SoC 表；未知 SoC、非 Android 和其他厂商设备不能据此自动选择核。
- 1、2、4、8 线程扫描只说明 8 线程在四个测试点中吞吐最高，不能证明已达到或尚未达到饱和点，也没有给出功耗与温度最优值。
- GPU 设备侧采样避免完整 logits 回传，但选中的 token id 仍返回 host；CPU/GPU 整机差异不能归因于这一个环节。
- `Duplicate()` 与 `std::swap` 只证明调用点没有显式复制；storage、布局、事件和 delegate 内部转换未核验时，不写成端到端 zero-copy。
- GPU 约束解码对非 host logits 执行完整回读、mask 与写回；Session Clone 和多候选 KV 转换有明确的 `memcpy` 路径。
- NPU 主模型允许 `kNpu | kCpu`，text embedder 单独以 CPU 编译；`Backend::NPU` 不能作为全图驻留 NPU 的证据。
- 后端 A/B 默认还可能改变 sampler backend；输出诊断从首个分叉 step 的 logits 开始，并分别控制激活精度、量化 kernel 与等待提示。
- 两台 Qualcomm 设备均未完成 NPU prefill 或 decode。已观察到的签名、访问和包代际条件不能被合并成唯一根因，NPU 能效也没有实测。
- `LiteRT-LM#2281` 只说明后端可能产生不同输出；冻结代码与浮点常识不能替代逐层对齐，也不能把所有差异自动判为正常。

## 当前仍存在的实验缺口

- 仍需匹配模型包、SoC 代际、QNN 组件与签名环境，完成 NPU 推理并采集吞吐、时延和功耗。
- 设备侧采样的独立收益、CPU/GPU 输出差异的逐层复现、Android 峰值内存均未完成有效测量。
- buffer 共享路径尚无 delegate/driver timeline，不能报告同步与内部复制的分项时间。
- 线程扫描尚未包含持续功耗、温度与更高线程数。
