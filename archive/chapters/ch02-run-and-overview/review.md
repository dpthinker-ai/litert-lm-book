## 本轮已纠正的关键事实

- Python 流式迭代单位是响应字典，不是 token 或 decode step；无文本的 step 还可能不触发回调。
- Init API 值是可能重叠的 phase duration 之和，不是无重叠墙钟时间；TTFT 由 prefill 时间与平均 decode step 组合，也不是首个流式回调的直接时间戳。
- benchmark 模式会强制等待 prefill 并使用固定 decode 步数，因此不能直接替代真实对话的端到端测量。
- CPU/GPU 吞吐差异只能说明阶段对后端的敏感度不同；等效字节估算把多项上下文相关成本折算在一起，不能当作 KV cache 的实测 DRAM 流量。
- 五层结构改为职责视图，不再声称所有代码只依赖相邻层。

## 当前仍存在的实验缺口

- 缺少缓存冷/热严格受控、带外部墙钟的初始化对照，以及首个回调时间的直接采样。
- 缺少硬件计数器与分阶段探针，现有端到端 tokens/s 不能独立判定 compute-bound 或 memory-bound。
