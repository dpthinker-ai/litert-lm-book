# 第三部分 · 模型加载、异构执行与投机解码

第二部分走通了推理流水线——输入变成 token，prefill 建立上下文，decode 逐个生成。本部分追问一个更实际的问题：这套流水线在真实设备上能跑多快，以及哪些机制决定了它的速度和内存占用。四章分别从 KV cache、模型文件与权重、异构后端和投机解码四个维度展开。

第 6 章聚焦 KV cache。自回归生成每步都要访问此前全部位置的 Key 和 Value——不缓存意味着第 1000 步要重算 999 份注意力，缓存则是用内存容量换掉这笔重复计算。这一章从容量公式出发，计算 KV cache 的内存占用和对 decode 带宽的影响，分析 `--max-num-tokens` 如何改变预留宽度和实测吞吐。随后转入实现层：双缓冲与单缓冲路径的差异、`Session::Clone` 的写时复制语义（Clone 本身不复制 KV 字节）、检查点的逻辑书签语义，以及 channel 内容过滤的回退与 refill 机制。

第 7 章讨论模型文件与权重。低比特量化能把权重从每参数 2 字节压到 0.5 字节，但文件中的 INT4 常量不等于运行时一定走低比特 kernel——中间还要经过图表示、后端编译和 kernel 选择三层。这一章顺着 `.litertlm` 容器格式的文件布局，逐层分析头部结构、section 索引、按需映射和 weight cache 的标识生成（注意：它不是内容哈希）。LoRA 的离线合并与运行时适配两条路径、懒物化的资源生命周期，以及双版本发布的存储与运行内存峰值计算，也在这一章给出可操作的部署核验流程。

第 8 章转向异构算力。同一份 `.litertlm` 文件分别用 CPU 和 GPU 运行时，速度不同，输出也可能不同。这一章从 `Backend` 工厂的分派逻辑出发，分析 CPU 的线程配置与 Pixel 亲和性、GPU 的设备侧采样与缓冲交接、NPU 的多子图路径与真机探测记录。buffer 共享不等于端到端零拷贝——这一章用三条标准（类型相容、布局一致、事件可传递）把“看起来没有复制”和“确实没有复制”区分开。最后一节给出后端输出差异的诊断方法：从首个分叉 token 倒查 logits、top-2 margin 和算子路径。

第 9 章讨论投机解码。decode 通常每生成一个 token 就要读取一次权重——如果一次权重读取能确认多个 token，带宽瓶颈的压力就会减轻。这一章用 LiteRT-LM 的 MTP（Multi-Token Prediction）实现为样本，走通草拟、批量验证和接受三个阶段的完整数据流，解释接受比例 r̂ 与理论条件概率 p 的口径区别，推导加速比公式 `(1+Gr)/q`，并给出盈亏平衡点的计算方法。多 token 返回对停止检测、回退逻辑和流式回调的影响也在这一章逐项核对。
