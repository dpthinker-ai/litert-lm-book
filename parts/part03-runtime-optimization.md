# 第三部分 · 资源管理与推理优化

第二部分说明了推理流水线：输入变成 token，prefill 建立上下文，decode 逐个生成。本部分讨论一个更实际的问题：这套流水线在真实设备上能运行多快，以及哪些机制决定了它的速度和内存占用。第 6 至 8 章建立缓存、权重与后端的资源模型。第 9、10 章分别讨论一次验证多个 token 和每个 token 只使用部分专家，分析这两种变化如何影响计算与权重访问。

第 6 章讨论 KV cache。全注意力生成会复用此前各位置的 Key 和 Value；缓存用内存保存这些张量，避免重复计算。局部注意力则只访问窗口内的位置，环形缓存可以限制对应层的物理容量。这一章从容量公式出发，计算 KV cache 的内存占用和对 decode 带宽的影响，分析 `--max-num-tokens` 如何改变预留宽度和实测吞吐。随后转入实现层：双缓冲与单缓冲路径的差异、`Session::Clone` 的写时复制语义（Clone 本身不复制 KV 字节）、检查点保存逻辑位置、会话状态和任务依赖的语义，以及 channel 内容过滤的回退与 refill 机制。

第 7 章讨论模型文件与权重。低比特量化能把权重从每参数 2 字节压缩到 0.5 字节，但文件中的 INT4 常量不等于运行时一定使用低比特 kernel——中间还要经过图表示、后端编译和 kernel 选择三层。这一章按 `.litertlm` 容器格式的文件布局，逐层分析头部结构、section 索引、按需映射和 weight cache 的标识生成（注意：它不是内容哈希）。LoRA 的离线合并与运行时适配两条路径、懒物化的资源生命周期，以及双版本发布的存储与运行内存峰值计算，也在这一章给出可操作的部署核验流程。

第 8 章转向异构算力。同一份 `.litertlm` 文件分别用 CPU 和 GPU 运行时，速度不同，输出也可能不同。这一章从 `Backend` 工厂的分派逻辑出发，分析 CPU 的线程配置与 Pixel 亲和性、GPU 的设备侧采样与缓冲交接、NPU 的多子图路径与真机探测记录。buffer 共享不等于端到端零拷贝——这一章用三条标准（类型相容、布局一致、事件可传递）把“看起来没有复制”和“确实没有复制”区分开。最后一节给出后端输出差异的诊断方法：从首个分叉 token 开始检查 logits、top-2 margin 和算子路径。

第 9 章讨论投机解码。decode 通常每生成一个 token 就要读取一次权重——如果一次权重读取能确认多个 token，带宽约束的影响就会减小。这一章用 LiteRT-LM 的 MTP（Multi-Token Prediction）实现为样本，说明草拟、批量验证和接受三个阶段的完整数据流，解释接受比例 r̂ 与理论条件概率 p 的口径区别，推导加速比公式 `(1+Gr)/q`，并给出盈亏平衡点的计算方法。多 token 返回对停止检测、回退逻辑和流式回调的影响也在这一章逐项核对。

第 10 章讨论端侧 MoE。总参数量与激活参数量分开后，模型保存规模、单步计算和专家工作集不再由同一个数描述。这一章从参数与字节换算出发，说明路由、分派、专家计算与合并，再比较 prefill、decode 和 MTP 验证时的专家访问。CPU 中当前专家的 FP32 权重展开、GPU 的分组与合并，以及单算子数值验证和完整模型运行，将前几章的内存和带宽分析用于稀疏模型。专家按需加载、缓存和预取作为设计选择讨论，其已有实现与待验证范围分别说明。
